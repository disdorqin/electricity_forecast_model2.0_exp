# Phase 13 — Shadow Trial Runbook

**Status:** PREPARATION (pending full-pipeline baseline)
**Created:** 2026-07-03
**Branch:** tune-timemixer

## Overview

This runbook defines the procedure for running IntradayTracker in real shadow mode alongside the main production pipeline. Shadow mode records what corrections *would have been* applied without actually modifying the final predictions.

**Prerequisite:** A full 4-model pipeline baseline must be established first. The current degraded pipeline (sgdfnet + timesfm only) produces sMAPE ~51%, making shadow evaluation meaningless.

---

## 1. Daily Intraday Pack Generation

The intraday correction pack is generated by the deep branch (`deep_model_for_electricity/`). Each day before 15:00 (D-1 cutoff):

```bash
cd deep_model_for_electricity/
python predict.py --date <YYYY-MM-DD> --mode INTRADAY \
  --output reports/local/daily/correction_pack_<YYYY-MM-DD>.csv
```

Pack requirements:
- Must contain hours 13-16 (cutoff_hour=12, target_hours 13-16)
- Must include: business_day, cutoff_hour, target_hour, base_pred, intraday_corrected_pred, intraday_confidence, policy_decision, fusion_weight, n_observed, residual_std_today
- Must NOT contain y_true for online mode

## 2. Main Pipeline Shadow Run

```bash
cd electricity_forecast_model2.0_exp/
python main.py <YYYY-MM-DD> \
  --target realtime \
  --prediction-mode INTRADAY \
  --intraday-pack reports/local/daily/correction_pack_<YYYY-MM-DD>.csv \
  --intraday-mode shadow
```

This runs the full pipeline (validation tap → real forecast → learner → fusion → intraday correction in shadow mode → classifier → final outputs).

## 3. Daily Output Verification

After each shadow run, check:

### 3.1 Manifest Check
```
outputs/<date>/intraday_mainline_manifest.json
```
Verify:
- `status`: "complete"
- `intraday_mode`: "shadow"
- `pack_rows` > 0
- `matched_rows` > 0
- `no propagation warnings`

### 3.2 Application Report
```
outputs/<date>/intraday_application_report.md
```
Verify:
- Policy decision distribution is reasonable
- Guardrail triggers are within expected range
- No unexpected DISABLED rows

### 3.3 Shadow Gain Report
```
outputs/<date>/shadow_gain_report.md
```
Record:
- `shadow_predicted_gain_pp`: should be near 0 (shadow doesn't change predictions)
- `would_have_corrected_rows`: how many rows would have been corrected
- `would_have_gain_pp`: estimated gain if corrections were applied

## 4. Promotion Criteria: Shadow → Low-Weight

Advance to low_weight mode ONLY when ALL conditions are met:

| Condition | Threshold | Rationale |
|-----------|-----------|-----------|
| Consecutive shadow days | >= 7 days | Statistical stability |
| Shadow gain consistency | > 0 for all 7 days | No regression |
| Negative bucket | Not worsened | Safety first |
| Policy disabled rate | < 50% | System is actually active |
| No propagation warnings | 0 warnings | Pipeline integrity |
| Baseline sMAPE (full pipeline) | < 25% | Meaningful base to improve upon |

## 5. Low-Weight Trial

```bash
python main.py <YYYY-MM-DD> \
  --target realtime \
  --prediction-mode INTRADAY \
  --intraday-pack reports/local/daily/correction_pack_<YYYY-MM-DD>.csv \
  --intraday-mode low_weight
```

Monitor daily:
- Actual sMAPE vs shadow baseline
- Negative bucket sMAPE
- Correction magnitude distribution
- Fusion weight utilization

## 6. Rollback Conditions

Immediately revert to shadow mode if ANY condition triggers:

| Condition | Threshold | Action |
|-----------|-----------|--------|
| Negative bucket worsening | > 1.0 sMAPE increase | Revert to shadow |
| Daily sMAPE worsening | > 0.5 sMAPE increase | Revert to shadow |
| Pack missing rate | > 20% of hours | Revert to shadow |
| Policy disabled rate | > 80% | Investigate, revert |
| Correction magnitude anomaly | > 3x historical mean | Revert, investigate |
| Propagation warnings | Any | Revert, investigate |

## 7. Escalation: Low-Weight → High-Weight

Additional requirements for high_weight promotion:

| Condition | Threshold |
|-----------|-----------|
| Consecutive low_weight days | >= 14 days |
| Low_weight gain | > 0.5pp improvement |
| Negative bucket | Stable or improved |
| Cutoff hour >= 14 | All pack rows |
| Confidence >= 0.55 | All pack rows |
