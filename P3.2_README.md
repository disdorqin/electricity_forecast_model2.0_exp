## What this is

P3.2 wires the validated P3 Extreme Price Correction System into the 3.0 pipeline as a
**controlled shadow** that is:

- **DEFAULT OFF.** Only runs with an explicit `--enable-extreme-price-shadow` flag (or the
  dedicated `extreme_price_shadow` pipeline). It never runs by default.
- **SHADOW-ONLY.** It writes exclusively to `outputs/runs/{date}/extreme_price_shadow/`.
  It never writes `final/`, never writes `submission_ready.csv`, and never replaces the
  original fused realtime prediction.
- **CUTOFF-SAFE / LEAKAGE-FREE.** The P3 classifiers are trained on history only (actuals
  strictly before the target day) and predict the target day. D-day actual and D14-after
  realtime actual are never used.
- **FAIL-SAFE.** Failures are never silently swallowed — they surface as a degraded shadow
  output + report, and are caught at the `main.py` hook so the main chain is never affected.

## Important: `main.py` / `cli/parser.py` integration

The 3.0 main-chain integration (the `--enable-extreme-price-shadow` flag, the
`extreme_price_shadow` pipeline choice, and the safe post-step hook in `main.py`) was
implemented in **efm3.0** (the canonical 3.0). Because `electricity_forecast_model2.0_exp`
uses a *different* `main.py`/`cli/parser.py` architecture (no `ledger_*` pipelines), the
root `main.py`/`parser.py` here are **intentionally NOT overwritten**.

The integration is captured verbatim as `p3.2_integration_patch_main_parser.diff` — apply it
against efm3.0's `main.py`/`cli/parser.py` to reproduce the wiring. The shadow module
itself is fully self-contained and test-covered on this branch, so it can be re-wired into
any 3.0-style entry point without modification.

## How to run (in efm3.0)

```bash
# dedicated pipeline
python main.py 2026-07-03 --pipeline extreme_price_shadow

# or as a safe post-step after any pipeline (default OFF)
python main.py 2026-07-03 --enable-extreme-price-shadow
python main.py 2026-07-03 --enable-extreme-price-shadow --shadow-only
```

## Safety guarantees (unchanged from P3.2 spec)

- Does NOT modify `electricity_forecast_model2.5` (read-only locked).
- Does NOT write `submission_ready.csv` or `final/` outputs.
- Does NOT replace the original fused realtime prediction.
- Does NOT mark champion / NORMAL-improvement.
- Does NOT use future actual or D14-after realtime actual.
- Default configuration does NOT enable the shadow.
